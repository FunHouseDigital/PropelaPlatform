# Semantic Review - Stage 21: Deployment & Production Readiness (v1)

## Issues Found (7)

### 1. Terser strips error reporter transport (CRITICAL)
`drop_console: true` in vite.config.js removes all `console.error` calls including the error reporter's `transport()` function. This makes the entire error reporting system a no-op in production.

**Fix:** Change terser config to use `pure_funcs` to only drop `console.log` and `console.debug`, preserving `console.error` and `console.warn`. Or better, replace `drop_console: true` with `pure_funcs: ['console.log', 'console.debug']`.

### 2. Service worker version not tied to build (MEDIUM)
`APP_VERSION` in `public/sw.js` is hardcoded as `'1.0.0'`. Since `public/` files are copied verbatim, the Vite define injection doesn't apply. Caches won't invalidate on new releases.

**Fix:** Add a comment documenting this limitation and change to use package.json version in a build script, or accept this as a known limitation and document that `APP_VERSION` must be bumped manually. For this PR, add a clear comment in sw.js about this requirement.

### 3. CSP allows unsafe-inline scripts (MEDIUM)
The nginx CSP includes `script-src 'self' 'unsafe-inline'` which is unnecessary for a Vite-built SPA (all scripts are external files).

**Fix:** Remove `'unsafe-inline'` from `script-src`. Keep it for `style-src` since Tailwind may inject inline styles.

### 4. useNetworkRetry dependency array captures config callbacks by identity (LOW-MEDIUM)
The hook's `execute` callback includes `config.onRetry`, `config.onError`, `config.onSuccess` in its dependency array. Since config is spread from options on every render, these are new references each time.

**Fix:** Store callbacks in a ref and read from the ref inside the callback, removing them from the useCallback dependency array.

### 5. Feature flag context frozen at mount (LOW)
`useMemo(() => getFeatureFlags(), [])` means flags never update after mount. The panel suggests instant feedback but consumers won't see changes until reload.

**Fix:** Add a comment documenting this is intentional (reload required) and ensure the FeatureFlagPanel UI mentions that a page refresh is needed for changes to take effect.

### 6. Nginx security headers lost in location blocks (MEDIUM)
When `add_header` is used inside a location block, it replaces ALL inherited headers. Security headers are missing from `/assets/`, `/index.html`, and `/sw.js` responses.

**Fix:** Include the security headers in each location block that uses `add_header`.

### 7. StatusPage exposes build metadata publicly (LOW)
The `/status` route has no access control. Git commit hashes, environment names, and build timestamps are visible to any user.

**Fix:** Add a note in the StatusPage component that in production this should be behind authentication. For now, acceptable as the app doesn't have real auth yet.

**Verdict**: NEEDS_CHANGES
