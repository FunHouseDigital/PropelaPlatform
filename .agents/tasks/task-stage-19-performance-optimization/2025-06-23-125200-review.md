# Performance optimization and code-quality tooling

Stage 19 adds bundle splitting, performance monitoring infrastructure, developer tooling (Prettier, Husky, lint-staged, enhanced ESLint), and targeted React memoization/debouncing. The approach lays down vendor chunk boundaries via Vite's `manualChunks`, introduces a `useWebVitals` hook and performance budget module for runtime monitoring, and applies `React.memo` and `useDebouncedValue` to the components most likely to benefit from reduced re-renders.

**Watch for:** The `useWebVitals` hook imports `onFID` from `web-vitals` v5, which removed that export — any consumer of the hook will crash at runtime (confirmed). Four new modules (`useVirtualList`, `useWebVitals`, `DevProfiler`, `performanceBudget`) are never imported by application code, making them dead code with no integration test coverage. The `useMemo` on the AppContext value object has a 90+ item dependency array that includes every state slice and every `useCallback`-wrapped updater, which will rarely prevent re-computation since any state change triggers at least one dependency change.

## High-level view

Bundle splitting creates five vendor chunks (react, recharts/d3, lucide, dnd-kit, react-router) via a `manualChunks` function in `vite.config.js`. The main risk is that `react-is`, a new production dependency used by recharts, doesn't match any chunk rule and will land in the fallback chunk rather than `vendor-react` or `vendor-recharts`.

The performance monitoring layer (`useWebVitals`, `performanceBudget.js`, `reactProfiler.js`) is scaffolding with no integration point. None of these modules are imported in the running app, so they contribute zero runtime value today. The `useWebVitals` hook has a broken import (`onFID`) that will throw if anyone activates it.

The ESLint config adds four `react-hooks/*` experimental rules (`static-components`, `set-state-in-effect`, `purity`, `immutability`) valid only in v7+ of the plugin — worth noting if the project ever pins to an older version.

Memoization targets the right components: `PlacementCard` (rendered in sortable lists), `DocumentCard` (rendered in grids), and the AppContext value object. The debounced-search pattern applied to `NurseDatabase`, `OutreachTable`, and `CommandPalette` introduces a UX subtlety — the search input updates instantly while results lag by 150–300ms, which can feel broken if no loading indicator is shown.

## `onFID` removed in web-vitals v5

`src/hooks/useWebVitals.js` line 3 imports `onFID` from `web-vitals`:

```js
import { onLCP, onFID, onCLS, onTTFB, onINP } from 'web-vitals'
```

The installed version is 5.3.0. The web-vitals v5 changelog explicitly removes FID in favor of INP, and the package's export map confirms no `onFID` export exists. Because `useWebVitals` is never imported in the running app, the build passes (Vite/Rollup tree-shakes it), but the module is broken: importing it in any component will throw `SyntaxError: The requested module does not provide an export named 'onFID'`.

## Chunk splitting and `react-is` gap

The `manualChunks` function routes dependencies into five buckets:

```
vendor-react    ← node_modules/react-dom, node_modules/react/
vendor-recharts ← node_modules/recharts, node_modules/d3-*
vendor-lucide   ← node_modules/lucide-react
vendor-dnd      ← node_modules/@dnd-kit
vendor-router   ← node_modules/react-router
```

`react-is` (newly added as a direct dependency to satisfy recharts' peer requirement at React 19) lives at `node_modules/react-is`. The `vendor-react` condition checks `node_modules/react/` (trailing slash), so `react-is` won't match. It lands in the catch-all app chunk or a default Vite chunk, undermining the intent of grouping all React runtime code together for cache coherence.

## AppContext `useMemo` effectiveness

The context value is wrapped in `useMemo` with a dependency array that enumerates every state variable (45 state slices) and every update function (45 `useCallback` refs). The `useCallback`-wrapped updaters have stable identity, so the real trigger set is the 45 state slices. Any single `setState` call changes one dependency and recomputes the memo. The only scenario where this `useMemo` provides value is if the provider re-renders for reasons unrelated to its own state (e.g., a parent re-render). Since `AppProvider` sits at the root and owns all its state, this effectively never happens. The memo adds a 98-line dependency list without measurable benefit.

## `useVirtualList` — unused scaffold with DnD incompatibility

No component imports this hook. It also won't compose with the existing sortable grid in `PlacementBoard` because DnD Kit's `SortableContext` expects all items to be mounted for drag detection. If virtualization is intended for `NurseDatabase`'s list mode, the hook would need to be wired into `GalleryView` or a new list-only view.

## Debounced search UX gap

`NurseDatabase` and `OutreachTable` wire `useDebouncedValue` between the search input's controlled state and the filtering `useMemo`. The input updates on every keystroke (responsive), but the filtered list doesn't update for 300ms. If the list is large enough for the user to notice the delay, there's no visual cue (spinner, dimmed results, "searching…" text) indicating that filtering is in progress. `CommandPalette` uses 150ms which is fast enough to be imperceptible, so this concern applies mainly to the two 300ms cases.
