# Property name fix across Document Management components

This change fixes a data model mismatch where the document management components referenced `nurse.name` instead of `nurse.fullName`, the actual property on nurse records. The fix touches all four sub-components (DocumentRepository, ComplianceChecklist, DocumentTemplates, VerificationWorkflow) at nine usage sites — search filtering, display rendering, and template data lookups. Task metadata files recording the feature's completion state are also included.

Watch for: No concerns. The fix is mechanically complete — every `nurse.name` reference in the document management module has been updated to `nurse.fullName`, and no partial renames remain. **(confirmed)**

## High-level view

The nurse data model uses `fullName` as its display-name property. The document management components were initially written using `nurse.name`, which would render as `undefined` in the UI for nurse names and break search filtering. The fix is a straightforward property rename — no logic changes, no behavioral shifts.

The task metadata (context.json, task.json, FEAT-002.json, FEAT-003.json) documents the completed feature workflow. These are agent bookkeeping with no runtime impact.
