# Global search command palette and navigation scaffolding

This change adds a full-screen command palette (`Cmd+K` / `Ctrl+K`), a header bar with breadcrumbs and smart suggestions, a quick-filters system with saved views, and the localStorage plumbing to persist search history and recently viewed entities. The approach is standard for the codebase: new state lives in AppContext with write-through to localStorage, new UI components slot into the existing Layout. The search is client-side substring matching over the four entity collections already in memory.

**Watch for:** Search results for Documents and Cohorts link to the list page, not the individual entity (confirmed). The `recentlyViewed` list is never populated by any code path in this diff — the feature is wired up but dead (confirmed). The click-outside handler in SmartSuggestions races with the toggle button, causing the panel to immediately re-close (likely).

## High-level view

The command palette lives at the Layout level with a global key listener. Keyboard navigation works against both live results and recent-searches. The search is O(n) substring matching per keystroke with no debounce — fine for current data volume, but will jank on larger datasets.

The quick-filters subsystem encodes active filters in URL query params via `useSearchParams`. Badge counts recompute on every render against the full data array. Saved views store only the preset ID, not the resolved criteria, making them fragile if preset definitions change.

The breadcrumb component parses the pathname statically through a label dictionary. It has no entity-name awareness despite the acceptance criteria calling for "Nurses > Jane Smith"-style breadcrumbs — raw IDs will appear for any sub-route.

The `recentlyViewed` state is initialized, persisted, and rendered in SmartSuggestions, but no code in this diff calls `updateRecentlyViewed`. The feature is dead at runtime.

## Command palette search and navigation

`searchAllEntities` is called inline during render with no `useMemo` or debounce. Every keystroke triggers a full iteration of all four entity arrays plus a sort.

The `path` assigned to Document results is always `/documents` and for Cohort results always `/cohorts`. Selecting a document search result navigates to the list page, not the specific document — unlike Nurse results which navigate to `/nurses/{id}`.

```js
// searchUtils.js — Document result path is unconditional
results.push({
  type: 'Document',
  ...
  path: '/documents',   // no entity-level route
});
```

## Breadcrumbs lack entity awareness

For a route like `/nurses/abc-123`, the second segment falls through to `segment.charAt(0).toUpperCase() + segment.slice(1)` — producing "Abc-123" rather than the nurse's actual name. The acceptance criteria call for entity-aware breadcrumbs, which requires looking up entity data from AppContext keyed by route params.

## recentlyViewed is wired but never populated

No component in this diff calls `updateRecentlyViewed`. The "Recently Viewed" section in SmartSuggestions will always be empty. A natural place to add tracking is in `handleSelect` inside CommandPalette (push the selected entity) or in page-level detail views on mount.

## SmartSuggestions panel interaction flaw

SmartSuggestions registers a `mousedown` listener on `document` to detect outside clicks. The Header's Sparkles button uses a regular React `onClick`. Because `mousedown` fires before `click`, clicking the button while the panel is open triggers `onClose` (panel closes), then `toggleSuggestions` fires (panel opens again). The panel can't be closed by its own toggle.

## Saved views fragility

A saved view stores:

```js
{ id: 'view-...', name: '...', module: 'nurses', filters: { filter: 'awaiting-docs' } }
```

Applying it sets `searchParams` to `{ filter: 'awaiting-docs' }`, which `QuickFilters` matches against preset IDs. If a preset is renamed or removed, the saved view silently becomes inert — it sets a URL param no preset recognizes, nothing filters, no error surfaces.
