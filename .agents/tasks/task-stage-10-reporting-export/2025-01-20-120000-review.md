# Reporting & Export module with drag-and-drop builder and configurable dashboards

A four-tab Reports page adds a report builder with drag-and-drop field ordering (@dnd-kit), a scheduled-reports CRUD interface, a bulk data export center with filtering, and a configurable dashboard widgets grid. Data flows through the existing AppContext/localStorage pattern: seed data initializes on first load, state lives in React, and every mutation writes through to localStorage. The module consumes existing domain data (nurses, placements, communications, documents) read-only and introduces its own persisted entities (scheduled reports, export history, dashboard layouts).

Watch for: KPI trend indicators are hardcoded strings with no historical comparison (confirmed). The CSV export in ExportCenter silently drops columns whose first row value is a nested object, which means exports lose data depending on which record happens to land first (confirmed). The "re-download" path in ExportCenter ignores the original filters, producing a different file than the original export (confirmed).

## High-level view

The Report Builder is the most complex piece: five report types each with their own field set, grouping aggregations that reshape data into summary rows, date filtering against string-typed ISO dates, and CSV export via a Blob URL. The data transformation logic is all inline in a single ~130-line `generateReport` callback. Date comparisons are lexicographic against ISO strings, which works for YYYY-MM-DD but would silently break for timestamps with timezone offsets.

Scheduled Reports is a UI-only CRUD layer with no backend scheduler or cron mechanism. The UI implies automated delivery (frequency, recipients, run history) but nothing triggers report generation on a cadence. The "Run History" section conflates schedule lifecycle state with execution outcome — a schedule paused after a successful run renders as "pending" in history.

ExportCenter downloads filtered domain data as CSV or JSON. The CSV generator infers columns from the first record's keys, filtering out object-valued columns. This heuristic fails when meaningful data lives in nested objects (e.g., `contractDetails` on placements) or when records have heterogeneous shapes. The re-download function regenerates from current unfiltered data rather than replaying the stored filters.

Dashboard Widgets introduces a second @dnd-kit grid with recharts-based chart rendering, a widget library, and save/load layout management. Widget config is not user-editable after creation, so adding multiple chart widgets yields duplicates. The layout persistence stores different shapes (string ID on init, full object after save), creating a potential inconsistency for any other consumer of `activeDashboardLayout`.

4. **No email validation in recipient input** — The scheduled report form accepts any string as a recipient email without format validation. A basic regex check would prevent typos from being persisted silently. (confirmed)
5. **Object URL leak on rapid export clicks** — `URL.revokeObjectURL` is deferred by 1 second via `setTimeout`, but nothing cancels prior timeouts if the user clicks export repeatedly. Under normal usage this is negligible, but in automated/test scenarios it accumulates unreleased blob URLs. (likely)
6. **Widget config not user-editable post-creation** — Adding a chart widget always defaults to `{ chartType: 'bar', dataSource: 'pipelineStages' }` with no UI to change it afterward, making multiple chart widgets redundant. Consider exposing config editing. (confirmed)

## CSV export column-inference gap

ExportCenter.jsx lines 117-122 determine which keys to include in CSV output:

```js
const headers = Object.keys(data[0]).filter((key) => {
  const val = data[0][key];
  return typeof val !== 'object' || val === null;
});
```

This checks only the first record. If `data[0]` has `contractDetails: { startDate: '...' }`, that entire field is dropped. The bigger issue is shape heterogeneity: if the first record has `null` for a field that other records populate with an object, the column is included but later rows will render `[object Object]`. Conversely, if the first record has an object where others have strings, the column is excluded and those records lose data silently.

For the Placements data type specifically, `contractDetails`, `matchHistory`, and other nested fields carry meaningful information that users likely want in an export.

## Re-download path ignores stored filters

When a user clicks "Re-download" on a history entry, `handleRedownload` (lines 163-210) fetches the full unfiltered dataset:

```js
case 'nurses':
  data = [...nurses];
  break;
```

The `entry.filters` object is stored but never applied. The re-downloaded file is always a full dump rather than the subset the user originally exported.

## Hardcoded KPI trend indicators

KPIContent renders trend arrows and percentage changes (`+5%`, `+3%`, etc.) that are string literals, not computed values. Since there's no time-series historical data in localStorage, there's nothing to compute against. The UI presents these as real trends, which could mislead users into thinking the system tracks changes over time.

## Run history conflates lifecycle and execution state

The "Run History" section derives entries from scheduled reports that have a `lastRun` timestamp, then maps `status: 'active'` to `'success'` and `status: 'paused'` to `'pending'`. This means a schedule that ran successfully then was paused shows as "pending" in history. Execution outcome and schedule lifecycle should be tracked separately.

## Widget layout persistence asymmetry

`saveLayout` updates `activeDashboardLayout` with a full layout object, while `initializeData` in storage.js sets it to just the layout ID string. DashboardWidgets handles both cases in its initializer (checking `typeof === 'object'` vs `'string'` and resolving accordingly), but this creates a data shape inconsistency in localStorage. On first load the value is a string; after the first save it becomes an object. Any other component reading this key expecting a string ID would break.
