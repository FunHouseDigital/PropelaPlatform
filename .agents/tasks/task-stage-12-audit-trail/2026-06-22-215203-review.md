# Audit Trail & Activity Logging Module

This change adds a four-tab audit trail section to the Propela Ops SPA: an activity feed, a system audit log table, a user session tracker, and a per-entity change history viewer with rollback. The implementation follows the established module pattern — deterministic seed data, localStorage persistence via storage helpers, AppContext integration, tab-based page component. The UI is read-heavy and filter-driven, with Recharts powering the session duration visualization.

Watch for: CSV export is vulnerable to formula injection in user-controlled fields (confirmed). The session duration chart can display nonsensical data because `loginTime` and `lastActivity` are independently random with no ordering guarantee (confirmed). The rollback feature writes to context state without concurrent-update protection, so rapid rollbacks could lose entries (likely).

## High-level view

The data layer seeds four collections from a single PRNG, gated by only the `activityFeed` key's existence — if the other three keys are independently cleared, they won't be re-seeded.

The four tab components are display-oriented except ChangeHistoryViewer, which writes rollback entries back through context. The rollback uses the render-closure `changeHistory` reference directly, making it susceptible to stale-state overwrites under rapid interaction.

The CSV export in AuditLogTable wraps only one of eight columns in quotes. The remaining fields — including user-supplied strings — are unescaped, creating both structural corruption and formula injection vectors.

The UserSessionTracker's bar chart relies on seed data where `loginTime` and `lastActivity` are independently random. Because neither is constrained to follow the other, the "duration" visualization can show meaningless values.

1. **CSV injection via unescaped fields** — The CSV export only wraps `details` in quotes. Wrap all fields in double-quotes (escaping inner quotes) to prevent formula injection and structural corruption. (confirmed)
2. **Session duration nonsense values** — `loginTime` and `lastActivity` are independently random; `lastActivity` can precede `loginTime`. Add a constraint in the seed generator so `lastActivity >= loginTime`. (confirmed)
3. **Stale-closure rollback race** — Rapid rollback clicks use the same stale `changeHistory` reference from the render closure. Use a functional state update or disable the button during the update. (likely)
4. **Partial seed integrity assumption** — Initialization checks only `activityFeed` existence. If any of the other three keys (`auditLog`, `userSessions`, `changeHistory`) are missing or cleared independently, they won't be re-seeded. Check all four or seed atomically. (confirmed)
5. **Style tag accumulation** — ActivityFeed injects a `<style>` element on every mount. Repeated navigation to the audit page accumulates duplicate style tags in the DOM. Move the keyframe to a CSS file or inject once with cleanup. (confirmed)

## CSV export field escaping

In `AuditLogTable.jsx`, the `handleExportCSV` function builds CSV rows by joining raw field values with commas:

```javascript
const rows = filteredAndSorted.map((entry) => [
  entry.timestamp,
  entry.user,
  entry.action,
  entry.entityType,
  entry.entityId,
  entry.ipAddress,
  `"${entry.details.replace(/"/g, '""')}"`,
  entry.severity,
]);
```

Only `entry.details` gets the quote-and-escape treatment. The `user` field comes from seed data that currently contains names without commas, but the data model doesn't enforce this — any user with a comma in their name (or a crafted name containing `=CMD(`) would break the CSV structure or trigger formula injection in Excel. The fix is straightforward: wrap every field in double quotes and escape inner double quotes, which is the RFC 4180 standard approach.

## Seed temporal ordering in UserSessionTracker

The seed generator picks `loginTime` and `lastActivity` independently:

```javascript
loginTime: generateTimestamp(rand, 2025, 2025),
lastActivity: generateTimestamp(rand, 2025, 2025),
```

Because both are random draws with no ordering relationship, `lastActivity` can be earlier than `loginTime`. The `calculateDuration` function uses `Math.abs(last - login)` which masks the problem numerically, but the chart and cards then display a "duration" that doesn't represent actual session time. The fix is to generate `lastActivity` as `loginTime + some random offset`.

## Rollback concurrency and state closure

In `ChangeHistoryViewer.jsx`, `confirmRollback` reads `changeHistory` from the component's render scope:

```javascript
const confirmRollback = () => {
  // ...
  updateChangeHistory([newEntry, ...changeHistory]);
};
```

If the user clicks Rollback on two different entries before the first re-render completes, both closures capture the same `changeHistory`. The second `updateChangeHistory` call overwrites the first's result. The modal gate makes this unlikely in practice, but the pattern is fragile if reused without a modal. A functional state update (`setChangeHistory(prev => [newEntry, ...prev])`) would eliminate the race.

## localStorage seed initialization gap

The guard condition checks only `activityFeed`:

```javascript
const activityFeed = getData('activityFeed');
if (!activityFeed || activityFeed.length === 0) {
  const seededAudit = seedAuditTrail();
  setData('activityFeed', seededAudit.activityFeed);
  setData('auditLog', seededAudit.auditLog);
  setData('userSessions', seededAudit.userSessions);
  setData('changeHistory', seededAudit.changeHistory);
}
```

If any of the other three keys are independently cleared from localStorage (dev tools, quota eviction), the app boots seeing `activityFeed` present and skips re-seeding, leaving the other collections empty. Either check all four keys or write them atomically behind a single version sentinel.

## ActivityFeed style injection

`ActivityFeed.jsx` renders a `<style>` tag containing `@keyframes activityFadeIn` directly in JSX. Every mount of the component appends a new `<style>` element to the DOM. In a single-page app where the user navigates away and back to the audit trail, these accumulate without cleanup.
